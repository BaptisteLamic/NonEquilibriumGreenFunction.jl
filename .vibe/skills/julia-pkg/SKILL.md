# Julia Pkg Dependency Management

This skill covers dependency management for NonEquilibriumGreenFunction.jl
using Julia's built-in package manager (Pkg). All commands assume the repo
root as the working directory.

## Project structure

```
Project.toml          # package deps, compat bounds (julia = "1.10")
Manifest.toml         # machine-generated, never hand-edit
test/Project.toml     # test env: Aqua, JET, TestItems/TestItemRunner,
                      # BenchmarkTools, PkgBenchmark, HssMatrices, JLArrays, ...
docs/Project.toml     # docs env: Documenter, Literate, CairoMakie, DSP, ...
```

There is **no** `benchmark/Project.toml`: the benchmark suite runs via
PkgBenchmark in the caller's active environment, which is the test
environment (`--project=test`).

`Manifest.toml` files (including in `test/` and `docs/`) are
machine-generated by Pkg. **Never edit them by hand** — always use
`Pkg.add`, `Pkg.rm`, `Pkg.pin`, `Pkg.resolve`, etc.

## Environments

- Package: `--project=@.` (or `--project=.`)
- Tests: `--project=test` (a full separate env; `Pkg.test()` resolves it
  automatically)
- Benchmarks: `--project=test` (benchmark deps live in the test env)
- Docs: `--project=docs`

## Key commands

```bash
# Resolve deps of the main environment
julia --project=@. -e 'using Pkg; Pkg.resolve()'

# Add a package dependency (updates Project.toml + Manifest.toml)
julia --project=@. -e 'using Pkg; Pkg.add("PackageName")'

# Remove a dependency
julia --project=@. -e 'using Pkg; Pkg.rm("PackageName")'

# Update all deps within compat bounds
julia --project=@. -e 'using Pkg; Pkg.update()'

# Check status
julia --project=@. -e 'using Pkg; Pkg.status()'
```

For the test and docs environments, prefix with the matching project flag,
e.g.:

```bash
julia --project=test -e 'using Pkg; Pkg.resolve()'
julia --project=docs -e 'using Pkg; Pkg.status()'
```

## Compat bounds

Compat entries in `Project.toml` constrain which versions are allowed, e.g.
`HssMatrices = "0.1"`, `julia = "1.10"`. Standard libraries
(LinearAlgebra, SparseArrays, Statistics) do not need compat entries, though
Aqua.jl's `deps_compat` check may flag them.

- After editing compat bounds by hand, always run `Pkg.resolve()` so the
  manifest matches.
- Use semver specifiers: `"0.1"` (caret-compatible), `"1"` (major),
  `"0.8, 0.9"` (range).
- When adding a dependency, let `Pkg.add` write the compat bound, or add it
  manually and re-resolve.

## Gotchas

- Never hand-edit any `Manifest.toml` (main, `test/`, `docs/`) —
  machine-generated; this is an explicit AGENTS.md rule.
- New package dependencies go in the top-level `Project.toml`; test-only
  deps (Aqua, JET, BenchmarkTools, PkgBenchmark) go in `test/Project.toml`;
  docs-only deps (Documenter, Literate, CairoMakie) go in
  `docs/Project.toml`.
- The docs environment needs the package itself: set up with
  `julia --project=docs -e 'using Pkg; Pkg.develop(path=dirname(pwd())); Pkg.instantiate()'`.
- Do not change the package UUID or version in `Project.toml` unless
  releasing a new version (AGENTS.md rule).
- If a dependency fails to resolve, check compat bounds first — a too-tight
  bound may prevent resolution. Run `Pkg.resolve()` and read the error
  output.
- JLArrays is a weak dependency (`[weakdeps]`/`[extensions]` in
  `Project.toml`): GPU support loads via the `JLArraysExt` extension and does
  not burden non-GPU users.
